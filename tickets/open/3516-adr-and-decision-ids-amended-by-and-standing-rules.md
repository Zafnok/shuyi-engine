# 3516 — ADRs say what they amend, supersede and govern, their amended-by links are generated, and decisions get ids and a standing-rules page

## Context

An accepted ADR is never edited to change its meaning
(`docs/adr/README.md`). So a rule changes section by section in later
ADRs. ADR-0008 is extended by 0012, 0024, 0057, 0058, 0062, 0081 and
0128. ADR-0003 is changed by 0011, 0015 and 0134. Agents and code
comments link straight to an ADR's file, so the file has to say what
changed it. Today two hand-written places say so, the old ADR's
`Status:` line and its row in the index, and the `write-adr` skill
(step 5) asks for both. They drift.

A blind-spot audit of the engine (2026-11) found this. It said "87 of
136 ADR files" disagree with the index. That count compared every ADR
id in the Status line with every id in the row, and the row also holds
"extends ADR-NNNN", which the files keep on a separate `Extends:` line.
So it overcounts. A script over `docs/adr/` on this branch (137 ADRs,
0001–0138 without 0136, which open PR 532 adds) counts this instead:

- 40 ADRs are said, by their Status line or their index row, to be
  extended, amended, narrowed or superseded by a later one. For 19 of
  them the two name different ADRs. Some examples:
  - ADR-0008's Status names 0057, 0058, 0062, 0081 and 0128. Its row
    names 0012, 0024, 0057, 0081 and 0128.
  - ADR-0020's Status says amended by ADR-0127, and 0127's `Amends:`
    line agrees. Its row says ADR-0129, and 0129 never names 0020. The
    row is wrong.
  - ADR-0024's Status names 0056 and 0128. Its row names 0076, 0079 and
    0128.
- Those 40 ADRs have 68 such links. About 21 of them have no `Extends:`,
  `Amends:` or `Supersedes:` line in the newer ADR to say so. Examples:
  0057 for 0008, 0084 for 0005, 0089 and 0107 for 0026.
- The forward lines exist but are not used: 54 ADRs have `Extends:`, 12
  have `Amends:` and 4 have `Supersedes:`. Nothing reads them.
- Nothing says which ADRs govern a crate or a path. To learn the rule
  for a file, an agent reads the index and every amendment.
- `cargo xtask check-docs` checks ADRs only for two files sharing one
  number (`ids::duplicate_adrs`, `crates/xtask/src/ids.rs`).

Nick's decisions have the same problem. `docs/decisions.md` is 98,019
bytes in 50 dated parts. Each part has his words verbatim and the rules
that follow from them: 4 parts have one `**Rule:**` line, and 46 have a
`**Rules:**` list, about 188 bullets in all, each opening with a bold
phrase ("- **The MVP is parity.** …"). No rule has an id,
and nothing marks one as revised (one line in the file says
"supersed"). The `work-ticket` skill tells a session to stop when
`decisions.md` doesn't hold an answer, and the only way to know is to
read the whole file.

Builds on: [ADR-0001](../../docs/adr/0001-record-architecture-decisions.md),
the `write-adr` and `ask-nick` skills, and the docs map
(`docs/README.md`).

**ADR-0136 (3034, done):** this ticket rewrites the Status line of every
ADR that something amends, and regenerates the index. The macroquad
research added ADR-0136 and amended ADR-0021 and ADR-0068; they get
their lines like the rest.

## Scope

**In:**
- **Forward lines are the source.** A newer ADR says what it changes, in
  its own bullet lines, which it may always edit:
  `- **Extends:**`, `- **Amends:**`, `- **Narrows:**`,
  `- **Supersedes:**`. Each names `ADR-NNNN`, an optional `§N`, and a
  short note in brackets: `ADR-0008 §4 (an image's sidecar is its import
  settings file)`. A whole-ADR `Supersedes:` (no `§`) makes the old one
  `Superseded`.
- **A `- **Governs:**` line** on each ADR not superseded whole: the
  repository paths it rules, as files or folders (a folder covers what
  is under it). No glob syntax, so no new dependency. A process ADR names
  its files (`tickets/`, `.claude/skills/write-ticket/`).
- **Generated backlinks.** `cargo xtask adrs --write` writes, in each
  ADR that a later one changes, a block under its bullet lines, between
  `<!-- changed-by: generated by cargo xtask adrs -->` and
  `<!-- /changed-by -->`: one line per later ADR, with its verb, section
  and note. The `Status:` line keeps only the state and the hand-written
  notes ("Accepted; its tickets are parked"). A generated block is
  navigation, not a change of meaning, so ADR-0001's rule holds.
- **A generated index.** The same command writes the index rows of
  `docs/adr/README.md`: number, title (the file's heading), and Status
  (the file's Status line, then the changed-by list in short form). The
  text above the table stays hand-written.
- **The check.** `cargo xtask check-docs` runs `adrs` in check mode. It
  fails: a generated block or index row that differs from what `--write`
  would make; a forward line naming an ADR that doesn't exist; a
  `Governs:` path that no tracked file is under; an ADR, not superseded
  whole, with no `Governs:` line.
- **`cargo xtask adrs-for <path>...`:** prints each ADR whose `Governs:`
  covers the path, oldest first, each with the ADRs that change it, and
  "no ADR governs this path" when none does.
- **Decision ids.** Each rule gets an id and topics in a code span after
  its bold lead: ``**Rule:** `D-YYYY-MM-DD.N` (topic, topic) …`` for a
  single rule, and ``- **The MVP is parity.** `D-2026-10-14.1` (scope)
  …`` for a bullet of a `**Rules:**` list. The id is the part's date and
  the rule's number within that day. Topics come from a list at the top
  of the file (about 15: `scope`, `licenses`, `parking`,
  `contributions`, `targets`, `networking` …). A rule a later decision
  replaces gets, at its end, `**Revised by:** D-YYYY-MM-DD.N.`
  The headings don't change, so links to
  `docs/decisions.md#2026-11-10-no-prs-or-issues-on-other-projects`
  keep working.
- **`docs/standing-rules.md`**, written by `cargo xtask adrs --write`:
  for each topic, the rules no later one revises, each a line with its
  id and a link to its part. A page or two. `check-docs` fails it when
  stale, and fails a duplicate id, a rule without an id, an
  unknown topic, and a `Revised by:` naming an unknown id.
- **The ticket lint** fails a `D-YYYY-MM-DD.N` in a ticket that
  `docs/decisions.md` doesn't hold.
- **The migration**, in this PR: forward lines added where they are
  missing (the about 21 above), each old Status line's changed-by text
  moved into forward lines and dropped, a `Governs:` line on every ADR,
  ids and topics on all the rules (about 192), and `Revised by:` on each rule a later
  part replaces. Where Status and the index disagree, read both ADRs and
  write the forward line that is true (0020's is 0127, not 0129).
- **The skills and the map.** `write-adr` step 4 and 5: write the
  forward line and `Governs:` in the new ADR, then run `cargo xtask adrs
  --write`; never hand-edit the old ADR or the index rows. `ask-nick`:
  a new part's rule gets its id and topics, and a rule it replaces gets
  `Revised by:`. `work-ticket`: read `docs/standing-rules.md` first and
  the decision parts it links, and run `adrs-for` on the files the
  ticket edits. The docs map gets rows for `docs/standing-rules.md`
  (generated) and the ADR lines.
- An ADR (the `write-adr` skill): ADRs' changes are recorded on the newer
  ADR, backlinks and the index are generated, `Governs:` says where an
  ADR applies, and decisions have ids. It amends ADR-0001 and uses its
  own format.
- No public type of an engine crate changes. `xtask` is not published.

## Implementation steps

1. `crates/xtask/src/adrs.rs` (new): parse each `docs/adr/NNNN-*.md`
   (not `0000-template.md`): number, heading title, the bullet lines
   (`Status`, `Extends`, `Amends`, `Narrows`, `Supersedes`, `Governs`;
   a line may wrap, as 0008's does), and the generated block. Parse a
   reference as `ADR-NNNN` or a link `[ADR-NNNN](NNNN-….md)` (0135
   writes the link form), with optional `§`s and a bracketed note. Skip
   `game ADR-NNNN`.
2. Build the graph: for each ADR, the list of later ADRs that change it,
   with verb, sections and note, in number order. A whole-ADR
   supersede sets the state.
3. Render: the changed-by block of each changed ADR, the index rows
   (Status line + `; ` + the short list, as today's rows read:
   "extended by ADR-0057 (§4: …)"), and `--write` / check modes. Keep
   the files' line endings LF.
4. `cargo xtask adrs [--write]` and `cargo xtask adrs-for <path>...` in
   `crates/xtask/src/main.rs`, with usage text. Call the check from the
   `check-docs` arm, beside `ids::duplicate_adrs`. Walk tracked files
   with `git ls-files` for the `Governs:` check, as `paths.rs` does.
5. Migrate the ADRs: for every link the old Status lines and the index
   rows hold today, make sure the newer ADR has the forward line (read
   both where they disagree). Then drop the changed-by text from the old
   Status lines, add `Governs:` to every ADR, and run `--write`. Diff the
   new index against the old one and check each changed row by hand.
6. ADR for the format; update `docs/adr/README.md`'s text above the
   table, `docs/adr/0000-template.md` (the new lines), and the
   `write-adr` skill.
7. Decisions: parse `docs/decisions.md`'s rules (the `**Rule:**` lines
   and each bullet of a `**Rules:**` list), their ids and topics, the
   topic list, and `**Revised by:**`. Add ids and topics to every rule. Read the file through once, oldest first, and mark each rule a
   later part replaces (for example a parked area that a later part
   unparks).
8. Render `docs/standing-rules.md` from step 7 in `adrs --write`, and
   check it, the ids, topics and `Revised by:` in `check-docs`. Add the
   page to the docs map.
9. In `crates/xtask/src/tickets.rs`, fail a ticket that names a
   `D-YYYY-MM-DD.N` that `docs/decisions.md` doesn't hold. Update the
   `ask-nick` and `work-ticket` skills, then run
   `pwsh -File scripts/sync-agent-skills.ps1`.

      0058, 0062, 0081 and 0128, or what reading them shows is true), and
