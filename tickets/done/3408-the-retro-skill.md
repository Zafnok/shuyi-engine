# 3408 — The retro skill, /retro, runs a retrospective over the last batch of merged PRs and files what it finds as tickets

## Context

Three retros have been run by hand: 2026-10-22 (#69, #70), 2026-11-08
(#314) and 2026-11-17 (PRs #379–#484, which became engine #488 and game
#740). Each one rebuilt the method from scratch. Nick asked for the
method to be kept as a skill he can call with `/retro`. The skill keeps
both his request (what a retro is for) and the process, including what
went wrong on 2026-11-17:

- a claim of a leak that was only half true;
- an id that crossed into the next ticket block (2100);
- a full block with no continuation row;
- an untracked report that failed the pre-push `typos`, and
  `check-docs` while this skill was written, so the report now goes in
  the session's scratchpad;
- a merge of `main` that failed `check-merges` after 3219 closed
  mid-PR, which made the PR be replaced.

## Nick input

None. He asked for the skill.

## Scope

**In:**
- `.claude/skills/retro/SKILL.md`, the shared source, and its Codex
  loader `.agents/skills/retro/SKILL.md`, generated by
  `scripts/sync-agent-skills.ps1`.
- The docs map's *What each task reads* gains rows for `33xx` and
  `35xx`. Both blocks are in `tickets/README.md` but had no row, and the
  skill tells a full block's opener to add one.

**Out (do not do):**
- Running a retro: the skill does that when asked.
- A tool that automates the retro. The reading and judging are the
  work, and listing the PRs is one `gh` command.

## Implementation steps

1. Write the skill from the 2026-11-17 session:
   - Nick's request, in his words;
   - its arguments;
   - the window, the reviewers and their brief;
   - checking claims by hand;
   - the report's shape;
   - filing: ids, parallel writers, owners, the release's list, the
     roadmap, the game's half, the checks, the PR, and a merge while it
     is open.
2. Run `pwsh -File scripts/sync-agent-skills.ps1`.
3. Add the two rows to `docs/README.md`.
