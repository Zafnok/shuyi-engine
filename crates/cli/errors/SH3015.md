# SH3015: The reveal kit doesn't verify

Class: operation, exit code 1.

`shuyi reveal verify` checked a reveal kit, the folder `shuyi reveal
prepare` wrote, and found it isn't as it was sealed. Each problem it
lists names a file:

- `reveal.ron`'s SHA-256 isn't the one in `reveal.ron.sha256`: the
  manifest changed after it was sealed, or the seal did;
- with `--digest`, `reveal.ron`'s SHA-256 isn't the digest given, the
  one published before;
- a capture, a receipt or `EVIDENCE.md` isn't there, or its SHA-256 or
  its length isn't what the manifest says;
- a file is in the folder and not in the manifest (only `reveal.ron`,
  `reveal.ron.sha256`, `CHECKLIST.md` and `.gitattributes` may be);
- the manifest names a path outside the kit, or is of a newer version
  than this `shuyi` reads.

A copy whose line endings git changed fails too: the kit's
`.gitattributes` keeps them as they are when the folder is committed
whole.

**How to fix it.** A kit is never repaired by hand: its digest is what
was published. Copy the kit again from a copy that verifies (an archive
of it, the commit that holds it). If the captures really changed, run
`shuyi reveal prepare` for a new kit, which has a new digest to publish.

For example:

```text
reveal: dist/reveal doesn't verify:
  captures/walk.png: its SHA-256 is 9f86d0…, the manifest says 2c26b4…
reveal: error[SH3015]: the kit doesn't verify (1 problem)
```
