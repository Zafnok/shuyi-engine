# SH3014: A step on GitHub or in git failed

Class: operation, exit code 1.

One step of `shuyi repos` failed: `gh` refused a call (making a
repository, a deploy key, a secret), `git` refused one (a commit with no
name and email set, a push without git's access to GitHub), or GitHub
answered what `repos` can't use (a folder's `origin` that isn't on
GitHub). The message says which step, and what `gh` or `git` said. The
steps before it are done, and the report lists them; those after it
weren't run. No private half of a key is left behind: its temporary
folder is removed whatever happens.

**How to fix it.** Fix what `gh` or `git` said. Then run `shuyi repos`
again: it makes only what isn't there, so it finishes the rest. Two
fixes come up often:

- A push or a clone git can't make over HTTPS: `gh auth setup-git` lets
  git use `gh`'s sign-in.
- A commit git refuses: set who you are, `git config --global user.name
  "<name>"` and `git config --global user.email <email>`.

For example:

```text
repos: error[SH3014]: the push failed
  it said: fatal: could not read Username for 'https://github.com': terminal prompts disabled
```
